# Overview summaries, historical extremes and the station network

The Overview keeps the containing-cell daily RhiresD/RprelimD estimate. Monthly totals and yearly extremes use the **same smoothed containing cell**, rather than borrowing a 441 km² area's statistics. This makes the quantities consistent; it does not improve the effective spatial resolution. MeteoSwiss recommends regional interpretation of RhiresD over 250–400 km². The ≥400-cell regional return-period model remains unchanged in Pro Mode. Local gauge measurements are available separately.

## Monthly reference and extremes

`data/reference/rainfall-summary` is a compact, checksummed descriptive reference for all 42,487 Swiss-mask cells. It uses the same 65 pinned annual files, 1961–2025, as the audited archive. `scripts/prepare_overview_history.py` reads only verified local source files. Explicit regeneration requires the repository environment and `requirements-history.txt`; routine builds do not download or regenerate it.

Each calendar month must contain every daily value for its cell. Store the number of complete months, average total, 10th/90th percentiles, largest monthly total with year, and mean number of ≥1 mm days. Yearly totals require all twelve months. These percentiles describe historical year-to-year variability, not uncertainty in the mean or a future prediction interval. Descriptive summaries include the full 1961–2025 record even when inspecting an earlier date; the separate frequency comparison still excludes the selected year.

For 1/3/5-day extremes, sum consecutive real daily values within calendar years, rank by amount (earlier date wins ties), select the largest window, and suppress overlapping windows until five remain. Missing windows are ineligible. Store five eligible candidates per year/cell and apply the same ranking globally; because windows never cross years, this preserves the global greedy selection. These are actual window rankings, not simply the five largest annual maxima. The Overview and address Pro Mode use these containing-cell dates; the regional Pro model recalculates its separate area-average amount for the selected date.

Independent NetCDF4 point reads, direct Python sums and full-history sorting at four established Swiss cells verify every displayed monthly and yearly statistic and all ranked windows. Fixtures: `tests/fixtures/overview-history.json`; explicit regeneration: `scripts/reference_overview.py`.

## Complete station access

`data/reference/station-network.json` indexes every inventoried daily precipitation series in SMN, SMN-precip, SMN-tower and NIME. Station codes can occur in more than one network; keep those histories separate, not silently spliced. The directory currently has 551 daily series and separately lists annual-only totalisers with official CSV access. Snow-only and tower stations without daily precipitation cannot supply a daily rainfall model. Annual totalisers use hydrological years (October–September), not calendar years.

Pro Mode → All stations & gauges loads only the selected station's official historical and recent daily CSVs. Parse the documented Windows-1252/semicolon format, preserve missingness, reject negative/nonfinite values and duplicate dates, retain URLs and content hashes, and give historical files precedence over overlapping recent files. An absent historical or recent file (404) is permitted for new or retired histories; at least one nonempty daily source is required and other errors remain errors. Original station records are not homogenised climate-trend records. The existing GEV/Gumbel/GPD/SMEV workers and complete-year/held-out safeguards are reused without mathematical changes.

The single station workspace now includes the clickable swisstopo map, full source histories, five ranked non-overlapping extremes, daily charts, accumulation explanation, CSV downloads and all four models. One map marker per station code avoids hiding duplicate network histories behind each other; the finder retains every separate series. The selected series takes precedence at its marker. Marker colours show selection only, not unrequested rainfall measurements at other stations. A second clickable map covers all FOEN gauges with published coordinates. Rainfall and gauge selections remain independent. The former sample-only explorer and model pages are removed; their old URLs redirect to the unified workspace. The fixed 18-station snapshot remains as a numerical regression/reference input, not a second product interface.

The FOEN directory includes all published gauge metadata, including historical/retired stations and sites without both Q and W. On-demand daily-mean queries permit at most 367 calendar days, below the documented 10,000-row cap. Original interval-start timestamps, native units and release flags remain inspectable. Gauge charts label UTC interval-start dates; lake recovery below uses explicit Swiss local daily labels. No catchment matching is inferred.

## Lake levels and experimental recovery comparison

`python scripts/prepare_water.py` (repository environment) explicitly retrieves real FOEN W daily means for 25 named Swiss lakes, 1970–present. This is a selected lake overview, not every lake in Switzerland. All published gauge metadata remains accessible in Pro Mode. Sources include exact GraphQL queries, retrieval timestamps and hashes. Provider daily interval-start timestamps and flags are retained; labels use Europe/Zurich so 22:00/23:00 UTC starts map to the intended Swiss local day. Unknown height units, duplicate labelled days and nonfinite observations fail preparation. Source daily means may have no release flag; display “not supplied” rather than inventing a validation status. A complete lake release is staged and promoted with rollback before replacing the previous dataset. The scheduled Pages workflow refreshes this dataset; historical requests are cached, while the current ten-year bucket and metadata are refreshed. A failed required preparation fails deployment, leaving the prior deployed site intact.

“Usual seasonal range” is explicitly the middle 50% (25th–75th percentile) of observed daily levels from 1991–2020 in a ±15 calendar-day window. At least 20 distinct years must contribute. It is a descriptive reference, not an official warning threshold or a claim that every day outside it is drought. February 29 uses its own position in a leap reference calendar. The shown lake date is independent of the rainfall calendar. Readings more than three days old suppress the outlook.

When below the seasonal lower bound, seek previous years with a measurement on the same month/day, a positive deficit and a deficit within max(5 cm, 50% of today's deficit). Use at most one start per year. Follow each case for up to 180 days; stop at the first missing observation/band or the start of the current calendar year. Recovery requires seven consecutive days within the moving seasonal band. Missing follow-up and non-recovery are **right-censored**, never counted as recovery or dropped.

With at least ten eligible starts, a Kaplan–Meier estimator gives a historical median time and supported recovery fraction by 180 days. If the curve never crosses 50%, no finite median is asserted. A horizon fraction is withheld if no case supports the horizon and survival remains positive. Five hundred deterministic resamples of year-start cases estimate a percentile sampling range; unsupported medians remain infinite rather than being discarded. The finite upper limit is withheld when its 97.5th percentile is not supported. Sparse cases show observations and a clear unavailable explanation instead of a made-up return date.

**This is a historical analogue comparison, not an operational forecast.** It is not conditioned on weather forecasts, inflows, evaporation, snowmelt or future outlet regulation. The matching rule is exploratory and has not been validated for forecast skill. Baseline observations can include the analogue years; do not present this as an out-of-sample prediction. Sampling ranges omit model choice, changing climate/regulation and measurement errors. A credible weather-driven recovery forecast is still a separate hydrological modelling task. Official context: [FOEN lake levels](https://www.bafu.admin.ch/en/lake-water-levels), [FOEN daily observations](https://data.bafu.admin.ch/en/dataproduct-water-observations).

## Annual comparison (5 November 2026)

Overview compares a selected archived year using all twelve complete calendar months, excluding that year from its reference. For the current release year, compare only January through the latest contiguous complete month with those same months in 1961–2025. Do not compare an unfinished year against complete years or extrapolate an annual total. A missing cell-month makes its period ineligible; at least 20 reference years are required. Historical percentile bands describe variation between years, not forecast confidence.

The additional checksummed `.years.u16.gz` chunks store cell/year/month totals at 0.1 mm resolution, with 65535 for missing. Ranks allow ties within the accumulated rounding tolerance. Independent NetCDF4 reads at four Swiss cells test all monthly totals. The descriptive reference retains the original monthly/extreme records unchanged. `prepare_year_overview.py` verifies each daily source hash, aggregates complete months and publishes a separate versioned current-year matrix. The scheduled Pages build runs this step after rainfall ingestion; it does not regenerate the national historical reference.

## Zurich and Constance prediction benchmark

`scripts/benchmark_lakes.py` is an explicit research preparation command, using the optional `requirements-history.txt` dependencies and already verified local archive. It writes `data/reference/lake-benchmark.json` and compressed real input series. These records include original FOEN query bodies/source hashes and MeteoSwiss versions/hashes. No additional dependency is needed by website visitors. This benchmark is static, not a daily forecast.

The direct ridge regressions predict 7/14/28-day level changes from origin-day level, 1/7-day level changes, preceding 3/7/30-day rainfall and annual sine/cosine. The rainfall indicator averages all Swiss-mask cells within ±20 km east/north of the gauge; every included value is required. It is explicitly **not** the hydrological catchment, especially for transboundary Constance. Rain labelled D−1 ends at 06 UTC on origin D; rain labelled D is unavailable at that daily origin and excluded. Require a complete prior seven-day level history, thirty-day rainfall history and complete target level window. Never interpolate gaps.

Train through 2009. Choose ridge penalty (1/10/100/1000) using 2010–2015 mean absolute error, independently for each horizon and for the model without rain. Calibrate nominal 90% absolute-error widths on this period, then refit through 2015. Neither training nor tuning targets cross into the next split. Test starts in 2016 and targets end by 2025. Compare MAE with unchanged-level persistence and the otherwise equivalent model without rainfall. Improvement uncertainty resamples paired whole test years (2,000 draws); overlapping daily origins are not independent trials. A retrospective revised-data test is not an archived real-time operational evaluation. Interval widths calibrated before the final refit are diagnostic and test coverage is reported explicitly.

At the initial split, level/seasonal predictors improved MAE against persistence for both lakes, while recent rainfall added less than 1 mm MAE at all horizons. These are not recovery-time results. The page does not issue a rainfall-conditioned recovery date: future weather, snowmelt, evaporation, inflows and outlet operation are absent, low-water-specific skill has not been established, and full transboundary catchment precipitation remains unresolved. Existing censored historical analogues remain a separate clearly labelled comparison. Before an operational outlook, add full catchment drivers, archived forecast inputs, low-water episode holdouts and calibrated recovery-event probabilities (seven consecutive days in the seasonal range).
