# Address-selected regional rainfall models

Pro Mode opens the selected address and rainfall date. A separate Station explorer retains the existing 18 stations, six river gauges, historical events, map, exports, GEV/Gumbel/GPD/SMEV, held-out comparisons and uncertainty tools. Regional observations never enter those station models.

## What the address model estimates

The address locates a containing 1 km cell. It selects a **fixed surrounding region**, then fits stationary annual maxima of **spatial mean precipitation**, not rainfall measured at a building. This follows MeteoSwiss's warning that the fine grid does not resolve local extremes. Their [RhiresD product documentation](https://www.meteoswiss.admin.ch/dam/jcr%3A4f51f0f1-0fe3-48b5-9de0-15666327e63c/ProdDoc_RhiresD.pdf) recommends regional interpretation and explains interpolation error, conditional bias and changes in the observation network. Aggregation does not eliminate these uncertainties or establish stationarity.

The mask comprises the same 1 km cells intersecting the buffered Swiss national boundary used by the monthly reference. Start with a 21×21 cell square centred on the address cell. If it contains fewer than 400 mask cells, expand its half-width to 15, 20, 25, 35 or 50 cells until at least 400 remain. Boundary-intersecting cells are included whole; the displayed km² figure is the nominal grid-cell area, not a precise clipped land-area measurement. Near borders the footprint is irregular and the search square may be wider. It is not a catchment. The footprint is fixed for every historical and selected day, without weather-dependent or missingness-dependent changes.

Every footprint cell must be valid for each spatial mean. Every day must be valid to retain that calendar year. No gaps are filled. For complete years, retain annual totals, number of regional wet days (area mean ≥1 mm), and the largest 1-, 3- and 5-day spatial-average accumulations plus their ending date. Sum days **after** spatial averaging; never average local annual maxima, which need not occur on the same date. Windows must lie wholly within the year; ties select the earliest window. Float64 summed-area calculations preserve the decoded float32 source values without rainfall quantization. Independent direct sums verify numerical agreement.

The initial reference uses all 65 pinned final annual RhiresD sources from 1961–2025. The selected recent accumulation uses exactly the same footprint and verified published daily fields, including their preliminary/consolidated status. If any required day or footprint value is missing, its comparison amount is unavailable; no smaller footprint or older day is substituted. Other user-entered thresholds and historical fits remain available when the daily lookup is valid.

## Models and uncertainty

Regional Pro Mode provides the existing independently verified **GEV and Gumbel** L-moment estimators, 1/3/5-day accumulation, fitting year range, selected-year exclusion, return-level curves, threshold return periods, annual exceedance probabilities, planning horizons, Q–Q plots and annual-maxima chronology. It runs the existing modelling worker, including its bootstrap failure/support safeguards. Default selected-year exclusion avoids using the analysed year when it is in the reference. Repeated fits use deterministic seeds and the full regional reference/cell identity.

500 or 1,000 resampled annual maxima give 80/90/95% pointwise sampling ranges. These exclude interpolation error, changes in gauges, model choice, future climate change and revisions of preliminary amounts. They are not prediction intervals or official MeteoSwiss estimates. The Gumbel comparison is a sensitivity check. Annual probabilities concern at least one exceedance in a year, not the frequency of an individual day in a calendar month. Overview retains the empirical same-month comparison for that purpose. GPD and SMEV remain available in the separate station explorer; this compact regional reference does not contain daily storm sequences needed to fit them.

## Overview facts and date choice

Yesterday's latest completed 06:00–06:00 UTC rainfall day is the default. Both views share the selected date, and the selector exposes the current published 90-day release, with missing days labelled. A button returns to the latest completed day. Earlier days require an explicit longer regional release; the full 1961–2025 archive supports the model and facts, not arbitrary daily field downloads through this selector.

The overview explains the empirical daily frequency in everyday terms and displays three regional facts: average annual precipitation total, average number of days with at least 1 mm, and the wettest regional day with its actual date. These are descriptive facts over complete reference years, not climate normals, trend estimates or record claims beyond 1961–2025. They are clearly separated from the containing-cell daily amount.

## Preparation, distribution and validation

`python run.py prepare-regional-models` reuses the pinned monthly reference's exact annual URLs, hashes and provider versions. Preparation is explicit, with all caches and outputs inside the repository. It produces `data/processed/regional-models/` and `outputs/regional-models.tar.gz` (about 118 MB compressed). Only the needed 64-cell chunk is fetched by a browser; chunks and cell index are SHA-256 verified. Stale address/day/duration results are hidden and pending daily requests are aborted. The reference manifest exposes all source versions and checksums.

`config/regional-models.json` pins an immutable data release tag and asset name, archive hash, manifest hash and reference ID. On the first push, an isolated `regional-reference` workflow job with release-write permission detects the missing asset, restores the baseline, downloads the pinned real sources, prepares the reference and verifies both exact file hashes before creating the data-only prerelease. This first publication can take substantially longer than an ordinary deploy. Existing assets are never overwritten; authentication/API failures other than 404 fail rather than being treated as a missing release. Subsequent runs skip preparation. The normal build job has repository-read permission and resolves the release asset by its pinned tag/name, then verifies content hashes before use. Pages restores and validates the reference before building; routine deployment never repeats the 9.4 GB source audit. The existing safe restoration logic never forwards GitHub authorization to storage redirects, validates before promotion and retains the previous output on failure. Local builds validate a prepared reference without downloading data. A checkout without prepared regional data still builds the separate station tools and displays unavailable regional history explicitly.

A separate Rasterio/NumPy extraction verified all 65 years around Bern, Geneva, Lugano and Davos: spatial averages, all 1/3/5-day maxima and dates, totals and wet-day counts. Twenty-four independent lmoments3/SciPy fits verify regional return levels. Versioned fixtures also preserve the independent daily Bern regional series for ongoing completeness/window checks. Dedicated tests cover fixed footprints, missing neighbours, missing years, date bounds, malformed chunks and the browser's selected-day spatial mean. The existing station model/held-out reference suites remain required.
